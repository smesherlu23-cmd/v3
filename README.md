# Centurio

Персональная панель запуска приложений для Windows, всегда доступная из трея.

Находит установленные программы в меню «Пуск», реестре, Steam и Epic Games,
раскладывает их по категориям и запускает в один щелчок. Набор — это
несколько программ, которые открываются вместе и расставляются по экрану
заданной раскладкой.

## Возможности

- **Поиск и запуск** из окна: `Ctrl+K`, имя, `Enter`.
- **Быстрые слоты** `Ctrl+1`…`Ctrl+9` для избранных программ, `Ctrl+Alt+1`…`9` для наборов —
  только в окне Centurio. Системных сочетаний программа не занимает: в браузере
  и офисе эти клавиши работают как обычно.
- **Наборы** — открыть несколько программ разом и разложить окна по сетке,
  половинами или 60/40; раскладку можно снять с текущего расположения окон.
- **Автопоиск** установленного с разбором найденного по одной карточке. На пустой
  библиотеке Centurio сам предлагает то, чем вы, судя по всему, уже пользуетесь:
  закреплённое на панели задач, запущенное, автозагрузку и ярлыки рабочего стола.
- **Не только программы**: сайт (`youtube.com`), папка или документ добавляются
  в библиотеку и в наборы так же, как программа.
- **Категории** с собственными значками, цветами и картинками.
- Работа из трея: окно прячется, закреплённые программы запускаются из меню значка.

## Установка

Windows 10 или 11, 64-bit. Для запуска из исходников нужен Python 3.9
или новее.

```bash
pip install -r requirements.txt
python main.py
```

Готовый установщик собирается из `installer/centurio.iss` (Inno Setup) —
см. раздел «Релиз».

## Релиз

```powershell
.\scripts\build_release.ps1
```

Только на Windows: сверяет версию (`app/__init__.py`, `pyproject.toml`,
`installer/centurio.iss` — той же проверкой, что и CI), гоняет линтер и тесты,
собирает `build\windows\Centurio.exe`, а если найден Inno Setup —
и `installer\Output\CenturioSetup.exe` с контрольной суммой рядом.
`-SkipTests` — пропустить проверки, `-SkipInstaller` — собрать только exe,
`-NoClean` — не чистить прошлую сборку.
Подробности: `Get-Help .\scripts\build_release.ps1 -Full`.

То же самое в CI делает `.github/workflows/release.yml`: ручной запуск
собирает и оставляет артефакты в прогоне, тег `v1.2.3` дополнительно создаёт
релиз. Версия в теге обязана совпадать с версией в исходниках.

Раздавать нужно **установщик**, а не голый `Centurio.exe`: рядом с ним
`flet build` кладёт набор DLL, без которых он не запустится.

### Подпись кода

Сборка пока не подписана, поэтому Windows покажет предупреждение SmartScreen,
а часть антивирусов сработает по эвристике: набор системных вызовов Centurio
(автозапуск, перечисление процессов, работа с
окнами других программ) по формальным признакам совпадает с профилем
шпионского ПО. Лечится это подписью, а не пересборкой.

Место для подписи в конвейере уже есть — `scripts/sign.ps1` подписывает и
приложение, и установщик, а без настроенной подписи печатает предупреждение и
не мешает сборке. Чтобы включить, задайте два секрета репозитория:

| Секрет | Что это |
|--------|---------|
| `SIGNING_DLIB` | путь к библиотеке-диспетчеру облачного сервиса подписи |
| `SIGNING_METADATA` | путь к JSON с параметрами учётной записи подписи |

Приватный ключ по правилам CA/Browser Forum обязан храниться на аппаратном
токене или в облачном HSM — файл `.pfx` в секретах GitHub не подойдёт.

## Ключи запуска

| Ключ | Действие |
|------|----------|
| `--hidden` | Запуск сразу в трей, без показа окна (только из исходников) |
| `--debug` | Подробный лог и вывод в консоль |

Собранному `Centurio.exe` аргументы, кроме `--debug`, передавать нельзя:
оболочка Flet принимает любой другой аргумент за адрес сервера «режима
разработчика» и не запускает Python. Поэтому в трей его отправляет не
`--hidden`, а поле «Окно: свёрнутое» у ярлыка — так устроен ярлык
«Автозагрузки», который ставят инсталлятор и сам Centurio.

Переменные окружения: `CENTURIO_DEBUG=1` — то же, что `--debug`;
`CENTURIO_WEB=1` и `CENTURIO_PORT` — запуск в браузере вместо окна. Второй
режим поднимает HTTP-сервер Flet на `127.0.0.1` (порт по умолчанию 8550) —
он для разработки, а не для повседневной работы, и требует отдельных
пакетов: `pip install "flet-web==0.28.3" "fastapi==0.112.2"` (с более
новым FastAPI flet-web 0.28 не стартует).

Повторный запуск Centurio не открывает второй экземпляр, а показывает окно
уже работающего. Глобальных сочетаний клавиш у Centurio нет; чтобы звать окно
с клавиатуры, закрепите его на панели задач — Win+цифра (номер значка слева)
запустит Centurio, и тот сразу покажет уже открытое окно.

Данные лежат в `%APPDATA%\Centurio\centurio-data.json`, кэш значков — в
соседней папке `icons`, лог — `centurio.log` там же. «Копия библиотеки» в
настройках сохраняет `centurio-backup-*.json` рядом и восстанавливает из
такого файла.

## Что происходит в фоне

- **Дозаполнение значков.** При каждом запуске и после каждого добавления
  Centurio достаёт недостающие значки из исполняемых файлов — напрямую через
  Win32, без запуска сторонних процессов. На большой библиотеке без кэша это
  заметная фоновая работа с диском. Тогда же прибирается кэш значков:
  удаляются файлы, которые больше никому не принадлежат и старше двух недель.
- **Обращения в интернет.** Для игр Centurio скачивает обложки и постеры:
  у Steam — с CDN Valve (`cdn.*.steamstatic.com`), передавая туда `appid`
  игры; у Epic Games — из публичного каталога
  (`catalog-public-service-prod06.ol.epicgames.com`, передаются namespace и
  id игры) и по ссылкам на картинки, которые этот каталог возвращает.
  Запросы идут при сканировании и при дозаполнении значков; файлы ложатся
  в кэш значков. Три отказа подряд отключают обращения к источнику до
  перезапуска, а выключенная настройка «Постеры для игр» — совсем.
  Больше приложение в сеть не ходит и своего сервера не поднимает
  (кроме режима `CENTURIO_WEB=1`).
- **Разбор найденного.** Программы, отмеченные в разборе как «не нужно» или
  убранные из библиотеки, запоминаются и при следующих проверках больше не
  предлагаются. Добавить такую программу можно вручную через «Добавить».
- **Слежение за запущенными.** Раз в несколько секунд снимается список
  процессов, чтобы отмечать открытые программы.

## Разработка

```bash
pip install -r requirements.txt
pip install pytest ruff

python -m pytest          # тесты
python -m ruff check .    # линтер
python tests/test_centurio.py   # тот же набор без pytest
```

Тесты, которым нужен Flet, пропускаются, если он не установлен, — но под CI
такой пропуск считается провалом, потому что там Flet ставится обязательно.

`python -m app.diagnose` печатает версии зависимостей, путь к данным и то,
что видит автопоиск, — с этого удобно начинать разбор проблем у пользователя.
На Windows дополнительно показывает сырой вывод каждого источника отдельно
от отфильтрованного списка: сколько нашли PowerShell (меню «Пуск» и Store),
реестр и папка `Programs`, сколько отсеялось как мусор, у скольких
Store-программ есть иконка. `python -m app.diagnose "vs code"` ищет по имени
в сыром выводе — если запись есть там, но не в итоговом списке, значит
проблема в фильтре; если её нет и там, до неё не достаёт сам поиск
(реестр/меню «Пуск»).

## Структура

| Каталог | Что внутри |
|---------|------------|
| `app/core/` | Логика без интерфейса: хранилище, запросы, раскладки, номера быстрого запуска |
| `app/platform/` | Работа с системой: поиск программ, запуск, окна, трей, автозапуск |
| `app/controllers/` | Сценарии: сканирование, наборы, разбор найденного |
| `app/ui/` | Экраны и виджеты на Flet |
| `app/infra/` | Логирование, debounce, снимок списка процессов |

Зависимости идут внутрь: `ui` знает про всё, `core` и `platform` не знают
про интерфейс. Это проверяется тестом `tests/test_imports.py`, который заодно
ловит импорты на несуществующие модули, включая отложенные внутри функций.
